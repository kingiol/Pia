## 2. 产品概述

Personal Investment Agent 不是一个被动等待提问的股票聊天机器人，而是一个理解用户投资体系、持续观察市场、主动发现异常、自动组织研究、执行确定性风险门禁的投资工作台。

它把以下信息汇总到同一个决策上下文中：

- 用户自定义交易规则和风险偏好；
- 市场广度、指数、行业、个股和量价数据；
- 公告、财报、新闻和事件；
- 用户持仓、成本、仓位和风险暴露；
- Agent 产生的分析、证据、分歧、结论和审批记录。

系统的责任边界：

```text
Agent        -> 理解、检索、分析、解释、编排
程序         -> 计算、校验、门禁、审计、重试
用户         -> 最终判断、授权和交易责任
```

## 3. 问题陈述

个人投资者通常遇到四类问题：

1. 信息分散：行情、财报、公告、新闻、持仓和自己的规则彼此割裂。
2. 研究不可复现：一次分析缺少证据、时间点和数据版本，无法回看。
3. 交易纪律不稳定：用户知道规则，但在市场波动时容易忽略规则。
4. 工具被动：传统终端和聊天机器人需要用户主动输入，不能持续发现问题。

产品要解决的是“持续、可追溯、受约束的投资研究与决策辅助”，不是承诺预测收益。

## 4. 目标与非目标

### 4.1 目标

- 建立市场、持仓和自定义规则的统一上下文。
- 让系统在事件发生后主动生成研究任务。
- 用多 Agent 产出结构化、可引用、可回放的研究结果。
- 用确定性 Rules Engine 阻断不满足条件的建议。
- 在 Research Workspace 中展示执行轨迹、证据、分歧和风险审核。
- 用人工审批保留最终授权。
- 为日后回测、盘中监控和半自动交易留下清晰接口。

### 4.2 非目标

- MVP 不承诺预测明日涨跌或稳定盈利。
- MVP 不做无人值守自动下单。
- MVP 不在没有数据授权时提供实时行情；首版只要求日线和收盘后数据。
- MVP 不实现完整券商交易柜台。
- MVP 不试图覆盖所有市场、资产类别和复杂衍生品。
- MVP 不把所有判断交给 LLM。

## 5. 用户与使用场景

### 5.1 主要用户

**纪律型个人投资者**

- 有自己的市场环境、仓位和止损规则；
- 需要持续复盘和提醒；
- 不希望 AI 越过自己直接交易。

**独立研究者**

- 需要快速比较行业、个股和事件；
- 关注证据来源和时间有效性；
- 需要保存研究过程以便复盘。

### 5.2 核心场景

#### 场景 A：收盘后市场复盘

1. 数据采集 Worker 完成当日数据同步。
2. Event Engine 生成 `MarketClose` 事件。
3. Market Agent 计算市场广度、情绪和异常。
4. Rules Engine 判断是否允许新增研究或买入候选。
5. Workspace 展示结论、证据和下一步行动。

#### 场景 B：持仓风险复核

1. 组合数据发现回撤、集中度或规则违背。
2. Event Engine 生成 `PortfolioRiskChanged`。
3. Portfolio、News、Technical Agent 并行研究。
4. Risk Agent 给出风险等级和建议动作。
5. 用户确认是否创建观察任务或人工处置。

#### 场景 C：个股研究

1. 用户输入股票或从候选列表打开研究。
2. Chief Agent 规划研究步骤。
3. Fundamental、Technical、News、Bull/Bear Agent 分工执行。
4. Research Manager 汇总证据、分歧和结论。
5. Rules Engine 和 Risk Review 给出门禁结果。

#### 场景 D：规则复盘

1. 用户查看历史建议和实际操作。
2. 系统对照当时的规则快照和数据快照。
3. 生成“规则满足/违反、建议是否被采纳、结果如何”的复盘记录。

## 6. MVP 范围

### 6.1 MVP 必须有

- 用户配置：股票池、持仓、风险偏好、交易规则。
- 股票池覆盖沪深主板、创业板、科创板、北交所和 ETF。
- 日线行情和基础财务数据导入。
- 市场广度、指数、行业和个股基础指标。
- 公告/新闻的结构化引用。
- Market、Sector、Stock Research、Technical、Portfolio、Risk Agent。
- Agent Trace、Evidence Panel、Bull/Bear Debate、Risk Review。
- Rules Engine：数据有效性、市场门禁、仓位门禁、个股规则。
- Event Engine：收盘事件、价格/成交量异常、公告事件、持仓风险事件。
- 建议状态：`BUY_CANDIDATE`、`SELL_CANDIDATE`、`HOLD`、`WATCH`、`NO_ACTION`。
- 研究任务、证据、结论和审批记录的持久化。
- Tauri Desktop 本地启动 Python Agent Sidecar。
- SQLite/DuckDB 本地存储、任务回放和追加式审计。
- 本地研究工作台、Agent Trace、Evidence、Risk Review 和人工审批。
- 本地通知和任务失败恢复。
- macOS 首发、Windows 同期支持的桌面启动和打包验证。

### 6.2 MVP 可以延后

- 盘中分钟级实时行情；
- 自动交易和券商写权限；
- Web/PWA 云端访问；
- Cloud Agent、远程调度和多设备同步；
- 手机原生 App；
- Tauri 安装包自动更新和跨设备同步；
- 多用户组织和团队协作；
- 向量数据库和复杂长期记忆；
- 高级回测和策略优化。

## 7. 功能需求

### 7.1 投资者 Profile

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-001 | 用户可维护风险偏好、投资目标和允许资产范围 | P0 | 保存后可在研究上下文看到版本化 Profile |
| FR-002 | 用户可维护交易规则，支持启用/停用和版本 | P0 | 新任务使用规则快照，旧任务不被改写 |
| FR-003 | 用户可维护持仓、现金和成本 | P0 | 组合暴露计算可复现 |

### 7.2 市场观察

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-010 | 展示市场广度、指数、行业和异常 | P0 | 每个指标包含 as-of 时间和数据源 |
| FR-011 | 支持股票池扫描和候选排序 | P0 | 排序结果可回放到输入数据 |
| FR-012 | 支持事件去重和冷却 | P0 | 同一事件在冷却窗口内不重复启动完整工作流 |

### 7.3 研究工作流

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-020 | 用户可创建研究任务 | P0 | 任务进入状态机并产生可见 Trace |
| FR-021 | Agent 以结构化状态协作 | P0 | 每个 Agent 输入/输出可审计 |
| FR-022 | 支持证据引用和失效时间 | P0 | 结论无法脱离证据单独展示 |
| FR-023 | 支持 Bull/Bear Debate | P1 | 双方观点、证据和裁决可见 |
| FR-024 | 支持失败重试和人工接管 | P1 | 失败任务可重试，不丢失已有结果 |

### 7.4 风险与审批

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-030 | Rules Engine 在建议前执行门禁 | P0 | 规则失败时不能进入可审批买入状态 |
| FR-031 | 风险审核独立于研究结论 | P0 | Risk Review 可否决研究结论 |
| FR-032 | 所有行动建议需要人工确认 | P0 | MVP 不存在无审批的订单写入路径 |
| FR-033 | 记录审批人、时间、规则版本和数据快照 | P0 | 审计记录完整可回放 |
| FR-034 | 用户可记录建议后的实际操作和结果，用于规则复盘 | P1 | 复盘记录关联原任务、规则快照、数据快照和观察时间 |

## 8. 非功能需求

| 类别 | 指标 |
|---|---|
| 可追溯性 | 每条结论关联任务、Agent、工具调用、证据和时间点 |
| 一致性 | 同一数据快照和规则快照可重放相同门禁结果 |
| 可用性 | 本地日终任务成功率目标 >= 99%，失败可重试；应用重启后任务状态可恢复 |
| 性能 | 收盘后标准研究任务 P95 完成时间 <= 5 分钟，不含外部服务不可用 |
| 安全 | API Key、持仓和券商凭据不出现在前端日志和模型上下文之外 |
| 可恢复 | Worker 崩溃后任务可恢复或明确失败，不静默丢失 |
| 可解释 | 结论必须展示证据、时间有效性和不确定性 |

## 9. 成功指标

### 产品指标

- 试点用户每周完成至少 3 次可回放研究任务。
- 收盘后复盘任务的人工复核完成率 >= 70%。
- 用户能在 2 分钟内找到一条结论的证据和规则门禁。
- 研究任务中 `NO_ACTION` 或明确阻断原因可见率 100%。

### 工程指标

- 任务状态无悬挂：`RUNNING` 超过 SLA 必须转为 `TIMEOUT` 或 `RETRYABLE`。
- 关键数据字段完整率 >= 98%。
- 规则引擎单元测试覆盖所有 P0 规则。
- 生产环境无直接从 LLM 到订单写入的路径。

## 10. 发布门

MVP 只有在以下条件同时满足时才可发布试点：

1. Tauri Desktop 可在无 Cloud Agent 的情况下启动本地运行时。
2. 日线数据同步、质量检查和失败告警可用。
3. 研究工作流可从事件启动并回放。
4. Rules Engine 可阻断不满足条件的建议。
5. Research Workspace 能显示证据和风险审核。
6. 所有行动建议都有人工审批记录。
7. 已完成本地数据备份、恢复和应急演练。
