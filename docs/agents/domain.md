# Domain docs

Pia uses a single-context layout. `GLOSSARY.md` at the repository root defines shared domain terms. `docs/adr/` holds architecture decision records (ADRs).

Before exploring the codebase, read the root glossary and any ADRs relevant to the area you will work in. Proceed if a file or directory is absent. Add glossary entries and ADRs when terms or decisions are resolved.

Use glossary terms in issues, specs, proposals, hypotheses, and tests. If a term is missing, check existing project usage and bring any unresolved vocabulary to `domain-modeling`.

If a proposal conflicts with an ADR, cite the decision and explain why it should be revisited.
